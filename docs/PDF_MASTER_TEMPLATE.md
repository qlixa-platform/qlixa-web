# PDF Master Template — QLIXA
*Специфікація системи генерації PDF-документів*
*Версія 1.0 — Липень 2026*

---

## ⚠️ ГОЛОВНЕ ПРАВИЛО

Цей файл — архітектура. Не стилі.
Всі кольори, шрифти та розміри беруться ВИКЛЮЧНО з `BRAND_STYLE_GUIDE.md`.
PDF Master Template не знає жодного HEX-коду і жодного назви шрифту.
Він знає тільки семантичні токени.

## 1. Семантичні токени кольорів

Замість HEX — завжди використовувати ці назви.
Реальні значення — в `BRAND_STYLE_GUIDE.md`.

```
COLOR.Primary         → основний акцент (teal)
COLOR.PrimaryDark     → темніший акцент (hover)
COLOR.Background      → фон сторінки (white)
COLOR.Surface         → фон карток, рядків (powder)
COLOR.Border          → лінії, розділювачі (light teal)
COLOR.TextPrimary     → основний текст (charcoal)
COLOR.TextSecondary   → другорядний текст (gray)
COLOR.TextMuted       → приглушений текст (gray light)
COLOR.Success.Bg      → фон успіху (light green)
COLOR.Success.Text    → текст успіху (dark green)
COLOR.Warning.Bg      → фон попередження (light amber)
COLOR.Warning.Text    → текст попередження (dark amber)
COLOR.Error.Bg        → фон помилки (light red)
COLOR.Error.Text      → текст помилки (dark red)
COLOR.Info.Bg         → фон інформації (powder)
COLOR.Info.Text       → текст інформації (gray)
COLOR.HeaderBg        → фон хедера (white)
COLOR.FooterBg        → фон футера (white)
COLOR.AccentLine      → акцентна лінія під хедером (Primary)
COLOR.TableHeader.Bg  → фон шапки таблиці (Primary)
COLOR.TableHeader.Text → текст шапки таблиці (white)
COLOR.TableRow.Even   → парні рядки (Surface)
COLOR.TableRow.Odd    → непарні рядки (Background)
```

## 2. Семантичні токени типографіки

Замість назв шрифтів — завжди використовувати ці назви.
Реальні значення — в `BRAND_STYLE_GUIDE.md`.

```
FONT.DocumentTitle    → назва документу в хедері
FONT.Heading1         → головний заголовок секції
FONT.Heading2         → підзаголовок секції
FONT.Heading3         → заголовок блоку
FONT.Body             → основний текст
FONT.BodySmall        → дрібніший текст
FONT.Caption          → підписи, мітки (UPPERCASE)
FONT.TableHeader      → шапка таблиці
FONT.TableCell        → вміст таблиці
FONT.Footnote         → виноски, disclaimer
FONT.KPI.Value        → велике число KPI
FONT.KPI.Label        → підпис KPI
FONT.ChecklistItem    → пункт чекліста
FONT.PageNumber       → номер сторінки
```

## 4. HEADER — однаковий у всіх документах

```
Структура:
┌─────────────────────────────────────────────────────┐
│ [ЛОГОТИП]              [НАЗВА ДОКУМЕНТУ            ] │
│ logo-name-slogan       [Дата генерації             ] │
│ _planets_black         [Номер / Період / Користувач] │
└─────────────────────────────────────────────────────┘
────────────── COLOR.AccentLine (2px) ─────────────────

Деталі:
- Логотип: ліворуч, width: 160мм, height: auto
- Назва документу: FONT.DocumentTitle, праворуч
- Підрядки хедера: FONT.BodySmall, COLOR.TextSecondary, праворуч
- Лінія під хедером: COLOR.AccentLine, товщина 2px
- Фон хедера: COLOR.HeaderBg

Обов'язкові поля:
  - Назва документу (завжди)
  - Дата генерації (завжди)

Опційні поля (якщо є):
  - Номер документу
  - Звітний період
  - Ім'я користувача / компанія
```

## 5. FOOTER — однаковий у всіх документах

```
Структура:
────────────── COLOR.Border (0.5px) ───────────────────
┌─────────────────────────────────────────────────────┐
│ [ЛОГОТИП малий]        [Службова інформація        ] │
└─────────────────────────────────────────────────────┘
                    [Сторінка X із Y]

Деталі:
- Логотип: ліворуч, width: 110мм, height: auto
- Службова інформація: FONT.Footnote, COLOR.TextMuted, праворуч
- Номер сторінки: FONT.PageNumber, COLOR.TextMuted, по центру знизу
- Лінія над футером: COLOR.Border, товщина 0.5px
- Фон футера: COLOR.FooterBg

Стандартний disclaimer (всі документи):
"Документ сформовано платформою QLIXA.
Інформація має виключно інформаційний характер та створена
автоматично на основі введених користувачем даних.
Документ не є офіційним рішенням державного органу,
юридичною консультацією або податковим висновком.
За потреби рекомендуємо перевірити інформацію відповідно
до чинного законодавства або звернутися до компетентного органу."

Номерація сторінок:
"Сторінка [N] із [Total]" — по центру, FONT.PageNumber
```

## 6. Блоки контенту — компоненти

### 6.1 Заголовок секції (Section Header)
```
Вигляд:    [█████ НАЗВА СЕКЦІЇ █████]
Фон:       COLOR.TableHeader.Bg
Текст:     COLOR.TableHeader.Text, FONT.Caption (UPPERCASE)
Padding:   6–8мм по вертикалі, 12мм по горизонталі
Відступ після: 1мм
```

### 6.2 Звичайний текст
```
Шрифт:    FONT.Body
Колір:    COLOR.TextPrimary
Відступ між абзацами: 4–6мм
```

### 6.3 Інформаційний блок (Info)
```
Фон:      COLOR.Info.Bg
Текст:    COLOR.Info.Text, FONT.Body
Border:   1px COLOR.Border, radius 8px
Padding:  10–14мм
Іконка:   ℹ️ або без іконки
```

### 6.4 Блок попередження (Warning)
```
Фон:      COLOR.Warning.Bg
Текст:    COLOR.Warning.Text, FONT.Body
Border:   1px COLOR.Warning.Text (opacity 30%), radius 8px
Padding:  10–14мм
Іконка:   ⚠️
```

### 6.5 Блок помилки (Error)
```
Фон:      COLOR.Error.Bg
Текст:    COLOR.Error.Text, FONT.Body
Border:   1px COLOR.Error.Text (opacity 30%), radius 8px
Padding:  10–14мм
Іконка:   ✕
```

### 6.6 Блок успіху (Success)
```
Фон:      COLOR.Success.Bg
Текст:    COLOR.Success.Text, FONT.Body
Border:   1px COLOR.Success.Text (opacity 30%), radius 8px
Padding:  10–14мм
Іконка:   ✓
```

### 6.7 KPI Картка
```
Структура:
┌─────────────────┐
│ МІТКА           │  ← FONT.KPI.Label, COLOR.TextSecondary, UPPERCASE
│ 1 234,56 €      │  ← FONT.KPI.Value, COLOR.TextPrimary
│ підпис/деталь   │  ← FONT.Footnote, COLOR.TextMuted
└─────────────────┘

Фон:      COLOR.Surface
Border:   1px COLOR.Border, radius 8px
Padding:  10–12мм
Grid:     2 або 3 картки в рядок залежно від кількості
```

### 6.8 Таблиця
```
Шапка:
  Фон:    COLOR.TableHeader.Bg
  Текст:  COLOR.TableHeader.Text, FONT.TableHeader
  Padding: 8–10мм

Рядки (чергування):
  Парні:  COLOR.TableRow.Even
  Непарні: COLOR.TableRow.Odd
  Текст:  COLOR.TextPrimary, FONT.TableCell
  Padding: 8–10мм

Межі:
  Між рядками: 0.3px COLOR.Border
  Зовнішні: немає (clean style)

Правила:
  - Текст в клітинці переноситься, не обрізається
  - Таблиця не розривається посередині рядка
  - На новій сторінці — повторити шапку
  - Числа: вирівнювання праворуч
  - Текст: вирівнювання ліворуч
```

### 6.9 Чекліст
```
Кожен пункт:
┌──────────────────────────────────────────────────────┐
│ □  Назва документу (примітка)     │ Дата │ Строк дії │
│    Нотатки: ______________________│      │           │
└──────────────────────────────────────────────────────┘

Фон (чергування): COLOR.Surface / COLOR.Background
Чекбокс: □ (порожній для друку) або ☑ (заповнений)
Шрифт: FONT.ChecklistItem
Розмір поля дати: фіксований (для ручного заповнення)
Примітка: FONT.BodySmall, COLOR.TextSecondary, в дужках

Правила:
  - Пункт не розривається між сторінками
  - Заголовок розділу завжди разом з першими 2 пунктами
```

### 6.10 Список (нумерований і маркований)
```
Маркований:
  • пункт    ← FONT.Body, відступ 5мм
  • пункт

Нумерований:
  1. пункт   ← FONT.Body, відступ 5мм
  2. пункт

Вкладений:
     – підпункт  ← FONT.BodySmall, відступ 10мм
```

### 6.11 Розділювач
```
Тонка лінія: COLOR.Border, 0.5px, повна ширина
Відступ до і після: 6–8мм
```

### 6.12 Рекомендація / Порада
```
Структура:
  [💡] Текст рекомендації

Фон:    COLOR.Info.Bg
Стиль:  як Info блок але з іконкою 💡
```

### 6.13 Блок підпису
```
____________________________    ____________________________
Підпис                          Дата

Шрифт: FONT.Body
Лінія: COLOR.Border, 0.5px
```

## 7. Правила багатосторінковості

```
✅ Завжди:
- Header повторюється на кожній сторінці
- Footer повторюється на кожній сторінці
- Шапка таблиці повторюється на новій сторінці
- Номер сторінки оновлюється автоматично

❌ Ніколи:
- Не розривати рядок таблиці між сторінками
- Не залишати самотній заголовок внизу сторінки
  (мінімум 2 рядки після заголовку)
- Не розривати чекліст пункт між сторінками
- Не розривати KPI картку між сторінками
- Не розривати Info/Warning/Success/Error блок між сторінками
```

## 8. Відступи між елементами

```
Після заголовку секції:    1мм
Між пунктами чекліста:     1мм
Між рядками таблиці:       0мм (padding в клітинці)
Між блоками (Info/Warning): 6–8мм
Між секціями:              10–14мм
Після хедера документу:    4–6мм
Перед футером:             автоматично
```

## 10. Логотип в PDF — технічне правило

```
Логотип ЗАВЖДИ завантажувати динамічно з сервера.
Не вбудовувати як base64 в код.

Алгоритм:
1. fetch('/logos/logo-name-slogan_planets_black.svg')
2. Отримати SVG текст
3. Конвертувати SVG → PNG через canvas (для сумісності з jsPDF)
4. Використати PNG в документі

Причина: якщо логотип зміниться на сервері —
всі PDF автоматично отримають новий логотип
без жодних змін в коді.
```

## 11. Головний принцип якості

Кожен PDF має виглядати так, ніби його підготувала людина
з відмінним відчуттям дизайну — а не автоматично згенерувала програма.

Документ має бути:
- Чистим і легким для читання
- Аккуратним і сучасним
- Мінімалістичним
- Візуально відповідним стилю сайту QLIXA
- Однаковим за структурою незалежно від типу

**Перевірка перед генерацією:**
- [ ] Header є і правильний?
- [ ] Footer є і правильний?
- [ ] Всі кольори з Brand Style Guide?
- [ ] Всі шрифти з Brand Style Guide?
- [ ] Таблиці не розриваються?
- [ ] Логотип завантажений динамічно?
- [ ] Disclaimer в футері є?
- [ ] Номерація сторінок є?
